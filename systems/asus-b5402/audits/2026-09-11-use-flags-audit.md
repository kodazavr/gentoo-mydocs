# Аудит глобальных USE-флагов ASUS ExpertBook B5402 — 2026-09-11

Аудит сопоставляет глобальный `USE` из `/etc/portage/make.conf`, точечные
правила `/etc/portage/package.use` и итоговые USE-флаги установленных пакетов
в VDB. Его цель — отделить системную политику от неактивных и слишком широких
правил. Изменений глобального `USE` в рамках аудита не выполнялось.

## Граница и метод

Для каждого глобального флага проверены установленные пакеты с включённым
флагом. Такой результат показывает текущих потребителей, но не предсказывает
USE-флаги будущих версий ebuild и новых пакетов. Поэтому отсутствие
потребителя — кандидат на решение, а не основание для автоматического
удаления.

`VIDEO_CARDS`, `INPUT_DEVICES` и `CPU_FLAGS_X86` не входят в этот документ:
это отдельные `USE_EXPAND`-переменные. В частности, обычный USE-флаг `zink`
не равен `video_cards_zink` из `VIDEO_CARDS`.

## Подтверждённая системная политика

Следующие флаги имеют несколько потребителей либо определяют сквозную
политику desktop, загрузки и безопасности. На дату проверки нет оснований
исключать их из глобального `USE`.

| Группа | Флаги |
|---|---|
| Wayland и мультимедиа | `wayland`, `opencl`, `vaapi`, `vulkan`, `alsa`, `gstreamer`, `pipewire` |
| Desktop и оборудование | `bluetooth`, `wifi`, `zstd`, `systemd`, `dbus`, `policykit`, `libinput`, `icu` |
| Загрузка и безопасность | `tpm`, `cryptsetup`, `openssl`, `secureboot`, `apparmor`, `audit`, `bpf`, `verify-sig`, `hardened` |
| Оптимизированные библиотеки | `asm` |
| Глобальные запреты по умолчанию | `-X`, `-xwayland`, `-elogind`, `-consolekit`, `-pulseaudio`, `-telemetry` |

`wayland` включён у 29 установленных пакетов, `vulkan` — у 15, а `systemd` и
`verify-sig` — у большого числа пакетов из базовой системы, desktop и
инструментов сборки. `icu` используют десять пакетов, включая Qt, SQLite,
Node.js, HarfBuzz и VTE.

### Pure Wayland и точечный X

`-X` задаёт глобальное значение по умолчанию, а не запрет на любую X-библиотеку
в системе. Некоторые пакеты намеренно собраны с `X`: QEMU, Mesa, `libglvnd`,
`libepoxy` и `virtual/opengl`. Для них нужен минимальный X-стек; Xorg-сессия
и X11 desktop не используются. Это соответствует выбранной модели: Wayland
остаётся базовым окружением, а X включается только у необходимых пакетов.

Аналогично `-xwayland` не запрещает установку `x11-base/xwayland` или
`gui-apps/xwayland-satellite`; он влияет только на ebuild, которые объявляют
одноимённый USE-флаг. Satellite оставлен как отдельный компонент, а не как
глобальное включение Xwayland для всего desktop.

`-pulseaudio` также подтверждён: совместимость с PulseAudio включена точечно
у PipeWire и Firefox, но не становится глобальной политикой.

## Уже исправленные устаревшие правила

После проверки владелец системы удалил две записи из `package.use`:

| Удалённое правило | Подтверждённая причина |
|---|---|
| `gui-apps/xwayland-satellite llvm_slot_21` | Установленный `xwayland-satellite-0.8.2` использует `llvm_slot_22`; позднее правило уже отключало слот 21 и включало слот 22. Старая строка создавала противоречие. |
| `=dev-lang/rust-bin-1.94.1 llvm_slot_21` | Установлена `rust-bin-1.97.1`, которая не объявляет LLVM slot USE-флагов. Точное правило для 1.94.1 больше не применялось. |

## Кандидаты без активных потребителей

Ни один установленный пакет не имеет включённых `mapi`, `vpp`, `zink`,
`networkmanager`, `udisks2`, `libnotify` или `acpi`. Эти флаги не требуются
для работы одноимённых служб или пакетов: например, наличие NetworkManager не
зависит от глобального флага `networkmanager`.

Это кандидаты на удаление из глобального `USE` после отдельной resolver-
проверки. Удаление обычного `zink` не должно менять `VIDEO_CARDS="intel iris
zink"`, но этот вывод также нужно проверить resolver-планом перед применением.

## Кандидаты на сужение области действия

| Флаг | Текущие потребители | Наблюдение |
|---|---|---|
| `sound-server` | PipeWire | Уже явно включён для `media-video/pipewire` в `package.use`; глобальная запись может быть избыточной. |
| `screencast` | Niri | Единственный потребитель — `gui-wm/niri`; флаг можно перенести в его правило `package.use`. |
| `lto` | GCC | `USE=lto` влияет только на `sys-devel/gcc`. Это отдельный механизм от `-flto=thin` в `CFLAGS`; перенос не отменит ThinLTO для C/C++. |
| `gles2` | `gst-plugins-base`, `mesa-progs` | Возможен точечный перенос, но требуется решить, нужна ли поддержка GLES2 новым мультимедийным пакетам по умолчанию. |
| `egl` | VS Code, `gst-plugins-base`, mpv | Возможен точечный перенос; текущая конфигурация выражает общую графическую политику. |
| `ffmpeg` | Qt Multimedia, libheif, PipeWire | Возможен точечный перенос, если поддержка FFmpeg не должна включаться у новых пакетов автоматически. |
| `v4l` | Qt Multimedia, FFmpeg, PipeWire | Решение зависит от политики камер и захвата видео. |
| `pgo` | семь пакетов, включая Firefox, GCC, Python, Bash, XZ и SVT-AV1 | Это ebuild-политика PGO, а не синоним `-O3`; перенос потребует нескольких точечных правил. |
| `custom-cflags` | Qt-модули, gmmlib и BPF toolchain | Большинство Qt-модулей уже закреплено в `package.use`; для сужения потребуются отдельные правила для оставшихся потребителей. |
| `btrfs` | containerd, Docker, Podman | Этот USE-флаг не включает Btrfs корневой ФС. Он определяет поддержку Btrfs в контейнерных рантаймах. |

## Отложенные границы

`nftables` включён только у NetworkManager и iptables. Он не настраивает
правила firewall и не включает сервис `nftables`; это поддержка в пакетах,
которые объявляют такой флаг. Решение отложено вместе с отдельным аудитом
firewall.

`dist-kernel` используют `intel-microcode` и `linux-firmware`; у
`intel-microcode` он уже задан точечно. Поскольку флаг связан с firmware и
загрузочной политикой, его не следует переносить или удалять только по числу
потребителей. Этот вопрос остаётся в kernel/firmware policy.

## Следующее решение и проверка

Перед любым изменением следует согласовать набор флагов, затем построить
resolver-план с `--pretend`, `--update`, `--deep` и `--newuse`. Только после
этого можно переносить флаги в `package.use` или удалять их из глобального
`USE`. Аудит не является разрешением на ребилд, обновление или очистку
пакетов.
